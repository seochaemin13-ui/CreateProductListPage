# 프로젝트 개요

본 프로젝트는 모바일 환경에 최적화된 쇼핑 환경을 제공하기 위해 설계된 **React 기반의 이커머스 프로토타입**입니다.
사용자가 상품을 탐색하고 장바구니에 담는 과정부터, 개인화된 결제 수단(카드)을 안전하게 관리하고 최종 결제에 이르는 전 과정을 끊김 없이 구현하는 데 중점을 두었습니다.

### 1. 프로젝트 목적
* **사용자 중심의 쇼핑 경험 제공**: 복잡한 결제 과정을 모바일 환경에 맞춰 단순화하고 직관적인 UI를 제공합니다.
* **안전한 결제 수단 관리**: 클라이언트 환경에서도 `CryptoJS`를 활용해 사용자 카드 정보를 암호화하여 저장함으로써 보안성을 확보합니다.
* **효율적인 상태 관리**: `Recoil`을 사용하여 장바구니, 상품 데이터, 결제 정보 등 복잡하게 얽힌 상태들을 선언적으로 관리하고 성능을 최적화합니다.

### 2. 주요 범위
* **Product Journey**: 상품 목록(`Home`)에서 상세 정보(`ProductDetail`) 확인 및 장바구니 담기 기능.
* **Cart Management**: 실시간 수량 변경에 따른 상품 금액 및 배송비 자동 계산.
* **Digital Wallet**: 가상 카드 등록(`AddCardForm`), 목록 확인(`MyCardList`), 및 카드 삭제 기능.
* **Mock Checkout**: 등록된 카드를 통한 가상 결제 승인 및 결과 확인(`PaymentSuccess`).

### 3. 개발 배경 및 필요성
* **모바일 쇼핑 비중 확대**: 웹 접근성을 넘어 모바일 앱과 같은 조작감을 제공하는 웹앱의 필요성이 증대됨에 따라, 탭 간격과 입력 폼 등을 모바일에 맞춰 설계했습니다.
* **개인정보 보호 강화**: 결제 수단 정보는 민감한 데이터이므로, 로컬 스토리지 저장 시 암호화를 필수적으로 적용하여 데이터 유출 위험을 최소화했습니다.

### 4. 제공 가치 (Value Proposition)
| 가치 구분 | 상세 내용 |
| :--- | :--- |
| **UX 최적화** | 관련 상품 추천 및 직관적인 수량 조절 등 구매 전환율을 높이는 UI 제공. |
| **보안 신뢰성** | AES 암호화 로직을 통한 안전한 카드 정보 관리. |
| **데이터 일관성** | Recoil Selector를 통해 장바구니 상태와 결제 금액 간의 데이터 불일치 방지. |
| **유연한 확장성** | 반응형 디자인과 모듈화된 컴포넌트로 향후 다양한 상품군 확장에 용이. |


# 시스템 아키텍처

본 프로젝트는 **React**를 기반으로 한 단일 페이지 애플리케이션(SPA)이며, **Recoil**을 활용한 선언적 상태 관리와 **CryptoJS**를 통한 데이터 보안 계층을 포함하고 있습니다.

### 1. 계층형 구조 (Layered Architecture)

애플리케이션은 크게 4개의 논리적 계층으로 구분됩니다.

| 계층 | 구성 요소 | 역할 |
| :--- | :--- | :--- |
| **View Layer** | Pages (`Home`, `Cart`, `ProductDetail` 등), Components | 사용자 인터페이스 렌더링 및 이벤트 수집 |
| **State Layer** | Recoil Atoms, Selectors | 전역 상태 관리 및 파생 데이터(총 금액 등) 계산 |
| **Logic Layer** | `cryptoUtils.js`, `Luhn Algorithm` | 데이터 암호화/복호화 및 유효성 검증 로직 |
| **Persistence Layer** | `localStorage` | 브라우저 종료 후에도 데이터를 유지하기 위한 로컬 저장소 |

---

### 2. 데이터 흐름 및 컴포넌트 연동 도식

애플리케이션의 핵심 데이터 흐름은 다음과 같은 구조로 유기적으로 연결됩니다.


#### **A. 상품 및 장바구니 흐름**
1. **탐색**: `Home` 또는 `ProductDetail`에서 상품 정보를 조회합니다.
2. **상태 변경**: 사용자가 '담기'를 클릭하면 `cartState`와 `cartQuantitiesState`가 업데이트됩니다.
3. **자동 계산**: `cartPriceSummaryState`가 변경된 상태를 감지하여 **총 상품 금액, 배송비, 최종 결제 금액**을 실시간으로 계산하여 `Cart` 페이지에 전달합니다.

#### **B. 결제 수단(카드) 보안 흐름**
1. **입력**: `AddCardForm`에서 사용자로부터 카드 정보를 입력받습니다.
2. **암호화**: `handleSubmit` 호출 시, `cryptoUtils`를 거쳐 민감 정보(카드번호, CVC, 비밀번호)를 **AES 알고리즘**으로 암호화합니다.
3. **저장**: 암호화된 데이터만 `cardsState`에 저장되며, 이는 `App.jsx`의 `useEffect`를 통해 `localStorage`에 동기화됩니다.
4. **출력**: `MyCardList`에서 카드를 보여줄 때만 `decryptData`를 통해 복호화하여 앞 8자리만 마스킹 처리 후 화면에 노출합니다.

---

### 3. 핵심 컴포넌트 간 관계

* **`App.jsx`**: `BrowserRouter`를 통해 라우팅을 제어하며, 전체 상태와 로컬 스토리지 간의 동기화를 담당하는 중앙 컨트롤러 역할을 수행합니다.
* **`recoil/atoms.js`**: 애플리케이션의 "Single Source of Truth"입니다. 모든 페이지 컴포넌트가 이 저장소를 참조하거나 업데이트합니다.
* **`VirtualCard.jsx`**: `AddCardForm`과 `MyCardList`에서 공통으로 사용되는 순수 UI 컴포넌트입니다.

---

### 4. 기술적 특이사항

* **Luhn 알고리즘**: 카드 번호 입력 시 프론트엔드 단에서 1차적인 유효성 검증을 수행할 수 있는 로직이 포함되어 있습니다.
* **Base URL 설정**: `import.meta.env.BASE_URL`을 활용하여 GitHub Pages 등 다양한 배포 환경에서도 에셋(이미지 등) 경로가 깨지지 않도록 설계되었습니다.


# 개발 환경 설정 및 규칙


### 1. 개발 환경 설정 (Getting Started)

프로젝트를 로컬 환경에서 실행하기 위한 단계입니다.

1.  **레포지토리 클론**:
    ```bash
    git clone [repository-url]
    cd [project-folder]
    ```
2.  **의존성 설치**: 프로젝트에 사용된 `CryptoJS`, `Recoil`, `React Router` 등을 설치합니다.
    ```bash
    npm install
    ```
3.  **환경 변수 설정**: `Vite` 환경에서 `GitHub Pages` 배포 경로를 맞추기 위해 `.env` 파일을 설정하거나 `vite.config.js`의 `base` 설정을 확인합니다.
4.  **로컬 서버 실행**:
    ```bash
    npm run dev
    ```

### 3. 코드 저장소 구조

본 프로젝트의 소스 코드는 기능적 역할에 따라 다음과 같이 체계적으로 관리됩니다. 특히 CSS 파일이 각 컴포넌트와 1:1로 매칭되어 있어 스타일 유지보수가 용이합니다.

```
/src
  ├── /pages                # 라우트별 페이지 단위 컴포넌트
  │   ├── Cart.jsx / .css        # 장바구니 페이지
  │   ├── Home.jsx               # 메인 상품 목록 페이지
  │   ├── PaymentSuccess.jsx / .css # 결제 완료 페이지
  │   └── ProductDetail.jsx / .css  # 상품 상세 페이지
  │
  ├── /recoil               # Recoil 상태 관리
  │   └── atoms.js               # 전역 상태(Atoms) 및 파생 상태(Selectors) 정의
  │
  ├── AddCardForm.jsx / .css # 카드 등록 폼 컴포넌트
  ├── MyCardList.jsx / .css  # 보유 카드 목록 및 결제 선택 컴포넌트
  ├── Card.jsx / .css        # 메인/상세에서 사용되는 상품 카드 UI
  ├── VirtualCard.jsx        # 시각적 카드 UI 공통 컴포넌트
  │
  ├── App.jsx / .css         # 라우팅 설정 및 데이터 영속화 로직
  ├── main.jsx               # 애플리케이션 진입점 및 MSW 초기화
  ├── cryptoUtils.js         # 데이터 암호화(AES) 유틸리티
  └── index.css              # 전역 스타일 및 Pretendard 폰트 설정
```

# 프로젝트에서 중요했던 지점

본 프로젝트 개발 과정에서 사용자 경험(UX)과 데이터 보안, 그리고 코드의 유지보수성을 높이기 위해 내린 주요 결정사항들입니다.

### 1. 사용자 경험(UX) 중심의 가상 카드 인터페이스
* **실시간 피드백**: 사용자가 카드 정보를 입력함에 따라 상단 `VirtualCard` 컴포넌트에서 카드 번호 마스킹과 이름이 실시간으로 반영되도록 설계하여 직관적인 확인이 가능하게 했습니다.
* **모바일 최적화 입력**: 카드 번호 4자리 입력 시 다음 칸으로 자동 포커스 이동, 숫자 전용 키패드 유도 등 모바일 환경에서의 입력 피로도를 낮추는 로직을 구현했습니다.
* **시각적 일관성**: 카드 등록(`AddCardForm`)과 목록 조회(`MyCardList`)에서 동일한 `VirtualCard` UI를 재사용하여 서비스 전체의 디자인 일관성을 유지했습니다.

### 2. 클라이언트 사이드 보안 강화 (Security-First)
* **민감 정보 암호화**: 서버가 없는 환경에서도 보안성을 확보하기 위해 `CryptoJS`의 AES 알고리즘을 도입했습니다.
* **데이터 보호**: 카드 번호, CVC, 비밀번호 등 민감한 결제 수단 정보는 브라우저 저장소(`localStorage`)에 저장되기 전 반드시 암호화 과정을 거치도록 강제했습니다.
* **마스킹 처리**: 카드 목록 출력 시 복호화된 원본 데이터 전체를 노출하지 않고, 앞 8자리만 보여주는 마스킹 로직을 적용하여 화면 훔쳐보기(Shoulder Surfing)와 같은 보안 위협에 대비했습니다.

### 3. 상태 관리의 효율성 및 데이터 정합성
* **선언적 금액 계산**: 장바구니 수량 변경에 따른 총액 및 배송비 계산을 수동으로 관리하지 않고, Recoil의 **Selector**(`cartPriceSummaryState`)를 활용해 상태 변경에 따라 자동으로 계산되도록 구현했습니다.
* **Single Source of Truth**: 모든 상품 정보와 장바구니 상태를 `atoms.js`라는 하나의 소스에서 관리함으로써, 상세 페이지와 장바구니 페이지 간의 데이터 불일치 문제를 원천적으로 차단했습니다.
* **영속성 유지**: `App.jsx`에서 `useEffect`를 통해 상태가 변경될 때마다 `localStorage`와 동기화하여, 사용자가 페이지를 새로고침하거나 브라우저를 껐다 켜도 쇼핑 정보가 유지되도록 설정했습니다.

### 4. 확장성을 고려한 컴포넌트 설계
* **비즈니스 로직 분리**: 암호화(`cryptoUtils.js`)와 금액 계산 로직(`atoms.js`)을 UI 컴포넌트에서 분리하여, 향후 다른 결제 수단이 추가되거나 계산 정책(할인 등)이 변경되어도 대응이 쉽도록 설계했습니다.
* **조건부 렌더링**: 장바구니가 비었을 때의 `empty-state` 처리나 결제 수단이 없을 때의 안내 문구 등을 세밀하게 구분하여 사용자 이탈을 방지했습니다.

### 2\. 문서 참조 방법

1.  **기능 구현 및 연동 확인**: `04.shopping_requirements.md`를 참조하여 상세 페이지에서 장바구니 담기, 수량 변경, 관련 상품 스크롤 등이 올바르게 연동되었는지 확인합니다.
2.  **데이터 일관성 유지**: 애플리케이션 내 어디서든 상태가 일관되게 유지되어야 한다는 요구사항을 준수하기 위해 `atoms.js`와 각 페이지의 연동 로직을 대조합니다.
3.  **결제 완료 프로세스**: 결제 성공 후 가격 정보와 함께 완료 창이 뜨고, 다시 상품 목록으로 돌아가는 흐름이 정상적인지 `PaymentSuccess.jsx`와 관련 문서를 통해 검증합니다.


### 3\. 문서 갱신 절차 (Update Procedure)

코드의 변경사항이 발생할 경우 다음 절차에 따라 문서를 최신화하십시오.

1.  **UI/UX 정책 변경**: 상세 페이지의 구성 요소(가격, 수량, 관련 상품 등)가 변경될 경우 `04.shopping_requirements.md`를 갱신합니다.
2.  **비즈니스 로직 수정**: 배송비 정책이나 수량 조절 로직이 변경되면 `03.cart_requirements.md`를 수정합니다.
3.  **보안 및 마스킹 규정**: 카드 정보 표시 방식이 바뀌면 `02.payments_requirements.md`를 업데이트하여 일관성을 유지합니다.


### 4\. 주요 참조 정보 요약

  * **상세 페이지**: 상품 이미지, 가격, 수량, 장바구니 담기, 관련 상품(자동 스크롤 가능) 및 설명 포함.
  * **결제 완료 창**: 결제 시 최종 가격 표시 및 '상품 목록으로 돌아가기' 기능 제공.
  * **배송비**: 10만 원 이상 구매 시 무료, 미만 시 3,000원 자동 부과.
