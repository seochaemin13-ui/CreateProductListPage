# 결제 모듈 프로젝트

## 프로젝트 개요

- 이 프로젝트는 React를 기반으로 구축된 사용자 친화적인 카드 등록 및 결제 인터페이스입니다.
  상품 목록에서 구매를 진행하고, 새로운 결제 수단을 안전하게 등록하며, 등록된 카드 목록을 관리하는 일련의 결제 프로세스를 제공합니다.
- 참여한 팀원: 서채민


## 개발 환경

* Framework: React 18.x
* Language: JavaScript (ES6+)
* Styling: CSS3 (Component-specific CSS Module 방식)
* State Management: React Hooks (useState, useRef, useEffect)

## 설치 및 실행 방법

프로젝트를 로컬 환경에서 실행하려면 다음 명령어를 입력하세요.

1. **의존성 패키지 설치**
```
npm install
```


2. **프로젝트 시작**
```
npm start
```


> 실행 후 브라우저에서 `http://localhost:3000`으로 접속합니다.


## 컴포넌트 구조

주요 컴포넌트의 역할과 흐름은 다음과 같습니다.

| 컴포넌트 명 | 역할 설명 |
| --- | --- |
| **App.jsx** | 애플리케이션의 메인 컨트롤러. `list`, `payment`, `addCard` 페이지 상태 관리 및 데이터 흐름 제어. |
| **Card.jsx** | 상품 개별 아이템 컴포넌트. 장바구니 담기 및 구매(결제 페이지 이동) 버튼 포함. |
| **MyCardList.jsx** | 등록된 카드 목록을 보여주는 페이지. 새 카드 추가 버튼 및 결제 선택 기능 제공. |
| **AddCardForm.jsx** | 카드 정보 입력을 위한 상세 폼. 자동 포커스 및 툴팁 가이드 기능 포함. |
| **VirtualCard.jsx** | 실제 카드와 유사한 UI를 제공하는 시각적 컴포넌트. 입력 정보 반영. |


1. **상품 목록 (`list`)** → '구매' 클릭 → **보유 카드 목록 (`payment`)**
2. **보유 카드 목록** → '+' 클릭 → **카드 등록 폼 (`addCard`)**
3. **카드 등록 폼** → '작성 완료' 클릭 → **보유 카드 목록**에 카드 추가

## 테스트 방법

본 프로젝트는 **Jest**와 **React Testing Library**를 사용하여 각 컴포넌트의 기능과 인터랙션을 독립적으로 검증합니다. 모든 테스트는 `__tests__/code/` 폴더 내의 테스트 파일이 `src` 폴더의 원본 코드를 참조하는 방식으로 동작합니다.

### 1. 테스트 실행 명령어

```
npm test
```

### 2. 주요 테스트 시나리오

* **상품 목록 및 장바구니**:
* 초기 로드 시 상품 목록 개수가 정확히 표시되는지 확인합니다.
* '담기' 버튼 클릭 시 헤더의 장바구니 배지 숫자가 증가하는지 검증합니다.


* **컴포넌트 인터랙션**:
* 상품 카드 내 버튼 클릭 시 텍스트가 '담기'에서 '담김!'으로 변경되고 전용 CSS 클래스(`added`)가 적용되는지 확인합니다.


* **카드 등록 폼 로직**:
* 카드 번호 입력 시 4자리가 채워지면 다음 입력 칸으로 자동 포커싱되는지 확인합니다.
* 모든 필수 정보(번호, 만료일, 소유자 등) 입력 시에만 '작성 완료' 버튼이 활성화되는지 검증합니다.


* **페이지 전환**:
* '구매' 버튼 클릭 시 보유 카드 리스트 페이지로, '+' 버튼 클릭 시 카드 등록 페이지로의 상태 전환을 테스트합니다.


## 유의사항 및 알려진 이슈

* **보안 가이드**: 실제 서비스 배포 시에는 보안 코드(CVC) 및 비밀번호를
  클라이언트 상태에 평문으로 저장하지 않도록 보안 처리가 필요합니다.
* **이미지 경로**: 현재 상품 이미지는 `public/img/` 경로를 참조하고 있습니다.
  이미지가 없을 경우 엑박이 발생할 수 있으니 해당 경로에 이미지를 배치해야 합니다.
* **초기 데이터**: 카드 정보는 현재 메모리(State)에 저장되므로,
  페이지 새로고침 시 초기화됩니다. (추후 LocalStorage 또는 API 연동 필요)

### 향후 업데이트 예정

현재 구현된 기능 외에 서비스의 안정성과 보안을 위해 다음과 같은 기능을 추가할 계획입니다.

* **데이터 지속성 (Persistence)**:
  * `LocalStorage`를 연동하여 브라우저를 새로고침하거나
  재접속하더라도 등록된 카드 정보가 유지되도록 업데이트할 예정입니다.
* **카드 삭제 기능**:
  * 카드 정보가 유지됨에 있어 반대로 삭제 가능하도록 할 예정입니다.
* **보안 강화 (Security)**:
  * `CVC`, `카드 비밀번호`, `카드 번호` 등 민감한 결제 정보를 클라이언트 단에서 암호화하여 관리하는 로직을 추가할 예정입니다.
  * 보안 마스킹 처리 고도화 및 입력 값에 대한 데이터 무결성 검증을 강화합니다.
