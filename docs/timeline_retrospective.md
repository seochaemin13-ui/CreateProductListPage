## 3단계: 개인적 인사이트 도출
- 2월 2일: 첫 스프린트 시작
  - 영향: 프로젝트의 초석을 다지며 팀의 초점과 우선 순위 설정.
  - 통찰: 스프린트의 시작이 팀 동기부여에 중요한 역할을 함을 인식.

- 2월 4일: 고객사 미팅
  - 영향: 고객사 미팅을 통해 프로젝트 방향 재조정 및 중요 요구사항 파악.
  - 통찰: 고객의 피드백과 요구사항이 프로젝트의 성공에 결정적임을 인식.

- 2월 5일: Git, Github 활용
  - 영향: Git, Github 을 이용하여 코드와 문서관리를 효율적으로 관리.
  - 통찰: 협업 툴의 숙련도가 팀 전체의 생산성과 커뮤니케이션 비용에 직결됨을 인식.

- 2월 11일: 상품 목록 페이지 배포
  - 영향: 제품의 첫 배포로 프로젝트 진행 상황과 성공적인 결과 확인.
  - 통찰: 제때 배포하는 것이 프로젝트의 모멘텀 유지에 중요함을 인식.

- 2월 20일: 첫 코드 리뷰 및 리팩터링
  - 영향: 코드 리뷰를 통해 코드 품질 향상 및 팀의 기술적 역량 강화.
  - 통찰: 리팩터링 과정이 프로젝트의 품질 및 유지보수에 중요하다는 것을 인식.

- 2월 27일: 프로젝트 중간 회고
  - 영향: 프로젝트 전반의 성과 및 문제점 평가.
  - 통찰: 정기적인 회고를 통해 팀의 성장 포인트와 보완할 기술적 영역을 명확히 확인.
 
- 3월 5일: Recoil 활용한 상태 관리
  - 영향: 전역 상태 관리 도입을 통해 복잡한 데이터 흐름을 단순화하고 개발 효율 증대.
  - 통찰: 적절한 상태 관리 도구 선택이 프로젝트 규모 확장에 따른 복잡도 제어에 핵심임을 인식.
 
- 3월 18일: React Router 적용
  - 영향: 멀티 페이지 라우팅 구현으로 사용자 경험(UX) 및 앱의 완성도 향상.
  - 통찰: 웹 애플리케이션에서 직관적인 네비게이션 설계가 사용자 만족도에 큰 영향을 미침을 인식.

## 4단계: 액션 플랜 수립
- 2월 2일: 첫 스프린트 시작
  - 영향: 프로젝트의 초석을 다지며 팀 모집과 자기소개 작성.
  - 통찰: 스프린트의 시작이 팀 동기부여와 목표 의식 설정에 중요한 역할을 함을 인식.
  - 액션 플랜: 다음 프로젝트에서는 스프린트 목표를 더 수치화하여 명확한 달성 기준 설정하기.

- 2월 4일: 고객사 미팅
  - 영향: 고객사 미팅을 통해 프로젝트 방향 조정 및 중요 요구사항 파악.
  - 통찰: 고객의 피드백과 요구사항이 개발 방향의 성공에 결정적임을 인식.
  - 액션 플랜: 미팅 시 요구사항 미리 메모하여 고객사의 요구사항이 무엇인지 바로 파악하기.

- 2월 5일: Git, Github 활용
  - 영향: Git, Github 을 이용하여 코드와 문서관리를 효율적으로 관리.
  - 통찰: 협업 툴의 숙련도가 팀 전체의 생산성과 커뮤니케이션 비용에 직결됨을 인식.
  - 액션 플랜: 효과적인 PR(Pull Request) 템플릿을 만들어 팀원 간 코드 이해도 높이기.

- 2월 11일: 상품 목록 페이지 배포
  - 영향: 제품의 첫 배포로 프로젝트 진행 상황과 성공적인 결과 확인.
  - 통찰: 실제 환경에 배포해 보는 과정이 잠재적인 버그와 성능 문제를 파악하는 데 필수적임을 인식.
  - 액션 플랜: github에서 deployment 하는 방법을 학습하여 배포 주기를 단축하고 안정성 확보하기.

- 2월 20일: 첫 코드 리뷰 및 리팩터링
  - 영향: 코드 리뷰를 통해 코드 품질 향상 및 팀의 기술적 역량 강화.
  - 통찰: 리팩터링 과정이 단순히 코드를 고치는 것을 넘어 코드의 유지보수성에 큰 영향을 미침을 인식.
  - 액션 플랜: 리뷰에서 지적받은 공통 사항을 체크리스트로 만들어 코딩 단계에서 스스로 점검하기.

- 2월 27일: 프로젝트 중간 회고
  - 영향: 프로젝트 전반의 성과 및 문제점 평가.
  - 통찰: 정기적인 회고를 통해 팀의 성장 포인트와 보완할 기술적 영역을 명확히 확인.
  - 액션 플랜: 회고에서 작성한 개선 사항을 다음에 즉시 반영하여 실행에 옮기기.

- 3월 5일: Recoil 활용한 상태 관리
  - 영향: 전역 상태 관리 도입을 통해 복잡한 데이터 흐름을 단순화하고 개발 효율 증대.
  - 통찰: 적절한 상태 관리 도구 선택이 프로젝트 규모 확장에 따른 복잡도 제어에 핵심임을 인식.
  - 액션 플랜: Recoil의 Selector 기능을 더 깊게 파고들어 데이터 가공 로직을 효율적으로 분리하기.

- 3월 18일: React Router 적용
  - 영향: 멀티 페이지 라우팅 구현으로 사용자 경험(UX) 및 앱의 완성도 향상.
  - 통찰: `location.state`를 활용한 데이터 전달의 유용성을 인식.
  - 액션 플랜: `useNavigate`의 `state` 기능을 활용하여 장바구니를 거치지 않는 직결제 프로세스 구축하기.
